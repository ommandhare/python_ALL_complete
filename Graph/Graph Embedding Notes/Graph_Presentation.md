# **Slide 1 – Introduction to Graph Embeddings**

## What is a Graph?

* A graph is a non-linear data structure consisting of **Nodes (Vertices)** and **Edges (Relationships)**.
* Nodes represent entities, while edges represent relationships between entities.
* Graphs are commonly used to model interconnected data such as social networks, recommendation systems, and knowledge graphs.

### Why Graph Embeddings?

Machine Learning models cannot directly process graph structures.

Graph Embeddings convert graph nodes into **dense numerical vectors** while preserving graph relationships.

---

### Graph Embedding Goal

```text
Graph
   ↓
Node Embeddings
   ↓
Machine Learning Ready Features
```

---

# **Slide 2 – Why Do We Need Graph Embeddings?**

### Problem

Graphs contain:

* Nodes
* Edges
* Relationships

Machine Learning requires:

* Numerical vectors
* Fixed-length feature representations

---

### Solution

Each graph node is transformed into a dense embedding vector.

Example:

```text
Om       → [0.21, 0.45, 0.82, ...]

Python   → [0.18, 0.49, 0.80, ...]
```

Nodes with similar graph structures receive similar embeddings.

---

### Benefits

* Preserves graph structure
* Enables similarity search
* Supports downstream ML models
* Reduces manual feature engineering

# **Slide 3 – How Node2Vec Generates Node Embeddings**

Node2Vec is a graph embedding algorithm that transforms graph structure into vector representations.

### Workflow

```text
Graph
   ↓
Node2Vec
   ↓
Biased Random Walks
   ↓
Graph Sentences
   ↓
Word2Vec
   ↓
Node Embeddings
```

---

### Process

* Start from every node
* Perform multiple controlled random walks
* Treat each walk as a sentence
* Train Word2Vec on generated sentences
* Produce vector representation for every node

---

# **Slide 4 – Understanding Node2Vec**

### Random Walk

A random walk traverses neighboring nodes.

Example:

```text
Om → Python → Rahul → Python
```

---

### Biased Random Walk

Node2Vec improves DeepWalk by controlling graph traversal using two parameters:

* **p (Return Parameter)** – Controls probability of revisiting previous node.
* **q (In-Out Parameter)** – Controls local vs global exploration.

---

### Advantage

Generates more meaningful graph sentences compared to completely random walks.

---

# **Slide 5 – Word2Vec & Node Embeddings**

### Role of Word2Vec

Word2Vec does **not** understand graphs.

It learns vector representations from graph sentences generated by Node2Vec.

---

### Example

Generated Sentences:

```text
Om Python Rahul

Om SQL Database

Rahul Python Pandas
```

↓

Word2Vec learns:

```text
Om → [0.12, 0.42, 0.81]

Python → [0.15, 0.45, 0.84]
```

Nodes appearing in similar graph contexts receive similar embeddings.

---

# **Slide 6 – Working with Node Embeddings**

Once embeddings are generated, they can be used for multiple analytical tasks.

### Similarity Search

Find structurally similar nodes.

Example:

```python
model.wv.most_similar("Om")
```

---

### Clustering

Group similar nodes using:

* K-Means
* Hierarchical Clustering

---

### Visualization

Reduce high-dimensional embeddings using:

* PCA
* t-SNE

This helps visualize node relationships in two dimensions.

## Key Takeaways

* Graphs represent entities and relationships.
* Node2Vec converts graph structure into meaningful training sequences.
* Word2Vec learns numerical representations from those sequences.
* Similar nodes receive similar embeddings.

## **Presentation Tip (Most Important)**

During your presentation, emphasize this sentence because it is the core idea behind the entire workflow:

> **"Node2Vec does not generate embeddings directly. It generates high-quality graph sentences through biased random walks. Word2Vec then learns node embeddings from those graph sentences."**

If your audience understands this one sentence, they will understand **80% of the Graph Embedding concept**. It also distinguishes the roles of **Node2Vec** (graph traversal and sentence generation) and **Word2Vec** (embedding learning), which is the most common point of confusion.
